# Mai Title

这是 `mai` 的标题模式。执行时读取 `../mai/references/workflow.md`，并按其中的确认优先、对话先展示、确认后写文档规则执行。

默认使用简体中文和用户沟通：上下文理解、提问、讲解、审查、风险说明、保存提示都用简体中文；标题文案必须始终先输出简体中文审核版，再输出用户指定的其它语言。

用户可以只用自然语言说“帮我写标题”。`--product` 优先使用产品资料文件夹，并递归读取其中所有可用文本资料；也兼容单个 Markdown 文件。缺少产品资料、平台、语言、长度或方案数量时，按 `workflow.md` 的引导式参数确认一次问一个数字选择题。

## 默认任务

- 文案类型：`title`
- 默认输出：标题 + 副标题
- 默认方案数：3 组；用户指定 `--count` 时按用户要求。
- 默认语言：`CN,EN,DE,ES`；若用户指定 `EN,DE` 等不含中文的语言列表，也必须实际输出 `CN,EN,DE`，且中文第一。
- 默认长度：`medium`。图片主标题、包装标题、小版位标题默认使用 `minimal`；SEO Listing 标题可使用 `full`。

## 必须确认

1. 平台：Amazon 或 AliExpress。
2. 标题用途：Listing 标题、图片主标题、包装标题、广告标题。
3. 是否需要品牌名前置。
4. 每种语言的字符/词数限制。
5. 长度档位：极简表达 / 中等 / 完整。
6. 是否要 SEO 强覆盖，还是更偏自然转化。
7. 是否用于图片/包装等固定版式；若是，必须检查最长单词，德语等语言避免长复合词。

## 输出前置规则

先在对话中输出：

- 理解确认
- 当前假设
- 语言顺序确认：简体中文永远第一
- 第一步：初步版本
- 第二步：第一次反思自查与优化建议
- 第三步：修正版
- 第四步：第二次反思与最终调整建议
- 第五步：最终版本
- 候选标题预览，使用编号方案和分组列表，不使用 Markdown 表格
- 每条标题的字符/词数统计，使用短列表，不使用 Markdown 表格
- 每条标题的最长单词/最长连续字符段检查
- SEO 关键词覆盖
- 合规风险

若平台、标题用途、语言、长度、方案数量或品牌名前置要求存在关键模糊点，先按 `workflow.md` 的阻断规则确认，不能直接生成。

用户确认后再写入文档；写入文档时可以使用 Markdown 表格做对照。
