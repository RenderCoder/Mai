# Mai Rich

这是 `mai` 的复杂上下文模式。执行时读取 `../mai/references/workflow.md`，并额外重视图片/草图/版面理解。

默认使用简体中文和用户沟通：上下文理解、提问、讲解、审查、风险说明、保存提示都用简体中文；图文案必须始终先输出简体中文审核版，再输出用户指定的其它语言。

用户可以只用自然语言说“根据这张图写文案”。`--product` 优先使用产品资料文件夹，并递归读取其中所有可用文本资料；也兼容单个 Markdown 文件。缺少版位、产品资料、平台、语言、长度、标签数量或版式限制时，按 `workflow.md` 的引导式参数确认一次问一个数字选择题。

## 适用场景

- 用户上传图片、草图、原型图、Figma 截图或详情页版面。
- 用户给出复杂文案 brief、多个文件、多个版位。
- 文案会进入二维平面排版，需要控制字数、行数、标签数量。
- 多语言共用同一套版式时，必须控制最长单词；德语等语言优先短词、短语和可自然换行表达，避免长复合词撑破文本框。
- 默认长度为 `minimal`，因为图片、草图和版面文案通常需要更短；用户可以指定 `medium` 或 `full`。

## 必须确认

1. 画面内容：画面里有什么、主视觉是什么、用户会先看到什么。
2. 版位目的：主图、副图、详情页、A+、包装、广告图。
3. 目标用户和使用场景。
4. 每个版位要解决的痛点。
5. 每个文本块的数量限制：标题、副标题、标签、按钮、说明。
6. 长度档位：极简表达 / 中等 / 完整。
7. 每个文本块的长度限制：字符数、词数、行数、建议断行。
8. 语言列表和是否需要本地化单位。
   - 即使用户只要求英文、德语等外语，也必须实际输出简体中文审核版，并把中文放在第一位。
9. 是否存在长单词排版风险，尤其是德语复合词、不可自然换行的长连续字符段。

## 输出前置规则

先在对话中输出：

- 画面/版式理解确认
- 信息缺口和当前假设
- 语言顺序确认：简体中文永远第一
- 第一步：初步版本
- 第二步：第一次反思自查与优化建议
- 第三步：修正版
- 第四步：第二次反思与最终调整建议
- 第五步：最终版本
- 多语言文案预览，使用编号方案和分组列表，不使用 Markdown 表格
- 每个文本块的字符数、词数、行数建议，使用短列表，不使用 Markdown 表格
- 每个目标语言的最长单词/最长连续字符段检查
- 二维排版风险
- 合规风险

若画面用途、版位、产品资料、语言、数量、长度或合规证据存在关键模糊点，先按 `workflow.md` 的阻断规则确认，不能直接生成。

用户确认后，再写入包含原始需求、画面理解、关键决策、最终文案和统计的 Markdown 文档；写入文档时可以使用表格做对照。
